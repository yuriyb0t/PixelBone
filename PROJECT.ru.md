# PixRig — паспорт проекта

**Версия:** 0.3.0  
**Дата документа:** 2026-11-26  
[English](PROJECT.md) | **Русский**

Технический паспорт проекта и заметки для передачи разработки. Публичное описание и полная инструкция по установке — в [README.ru.md](README.ru.md).

## Что это

PixRig — расширение для Aseprite на Lua:

**2D-скелет (кости) → «кожа» (силуэт из капсул) → экспорт слоями и кадрами в спрайт.**

Рабочее название — **PixRig**.

## Конечная цель

Импорт 3D-анимации из **GLB/glTF/BVH**, включая риг **Mixamo**, ретаргет на 2D-скелет и получение пиксельной анимации.

Отложенная фишка — **«умные кости»**, как в Moho: художник рисует крайние позы, а угол кости ведёт деформацию пикселей.

## Среда и ограничения

- Проверки при разработке выполнялись в **Windows**, в **Aseprite 1.3-rc4-dev**.
- В другой среде доступна более новая версия Aseprite, но этот документ не подтверждает проверку всех функций в ней.
- Общение по разработке ведётся по-русски; для сообщений о результатах проверок используются скриншоты.
- Часть правок готовилась в среде ассистента без Aseprite и интерпретатора Lua. В этой среде код не запускался. Имеющиеся подтверждения работы — ручные проверки разработчика и тесты логики.
- Каждую правку нужно проверять в целевой среде. Нельзя молча менять статус возможности с «написано» на «проверено».

## Установка

Полная инструкция — в [README.ru.md](README.ru.md#установка).

### Готовый пакет

1. Получите `pixrig-<version>.aseprite-extension` со страницы Releases, если пакет опубликован, либо соберите из исходников.
2. Закройте окна PixRig.
3. Откройте в Aseprite **Edit → Preferences → Extensions**.
4. Удалите старую версию PixRig через **Uninstall**.
5. Через **Add Extension** выберите пакет `.aseprite-extension`.
6. Перезапустите Aseprite.
7. Откройте **RGB-спрайт** и запустите **File → PixRig...**.

Не кладите пакет или распакованные исходники вручную в папку `extensions` Aseprite. Перед установкой не распаковывайте пакет и не переименовывайте его.

## Сборка и тесты

Из корня репозитория:

```sh
python3 build.py
```

Альтернатива для Windows через Python Launcher:

```powershell
py -3 build.py
```

Результат:

```text
dist/main.lua
dist/pixrig-<version>.aseprite-extension
```

`build.py` только собирает и упаковывает расширение. Он не устанавливает его и не проверяет интеграцию с Aseprite.

Тесты логики, нужен **Lua 5.3/5.4** в PATH:

```sh
lua tests/test_rig.lua
```

Тесты не затрагивают API Aseprite. Интерфейс, ввод, воспроизведение, изменение спрайта, теги, создание кадров и экспорт требуют ручной проверки в Aseprite.

## Модель данных в `sprite.data`

### Кость

| Поле | Значение |
| --- | --- |
| `id` | Идентификатор кости |
| `name` | Имя кости |
| `parent` | ID родительской кости; `0` — корень |
| `connected` | Связь с родителем |
| `ax`, `ay` | Координаты головы |
| `bx`, `by` | Координаты хвоста |
| `ra`, `rb` | Радиусы головы и хвоста |
| `group` | ID группы кожи; `0` — вспомогательная кость / без группы кожи |
| `mirrorOf` | ID кости, которую зеркалит эта кость |

Координаты — в пикселях спрайта. Центры пикселей находятся в `n + 0.5`.

### Группы кожи и контур

Группы хранятся в виде:

```lua
{id, name, color}
```

Новые кости получают активную группу.

Режим контура: `none | pixel`, с настраиваемым цветом контура.

### Анимации

Запись анимации:

```lua
{id, name, frames, fps, interp, keys}
```

Ключи индексируются так:

```lua
keys["<boneId>"]["<frame>"] = {
  rot = 0, -- градусы вокруг головы кости
  dx = 0,
  dy = 0,
}
```

- Ключи JSON-объектов — строки, включая индексы костей и кадров.
- `rot` вращает кость вокруг её головы в rest-позе.
- `dx` и `dy` — смещения, применяются только к корню.
- Поза рассчитывается через **FK от rest-позы**: кость вращается вокруг своей rest-головы, затем следует преобразованию родителя.
- `rig.rev` растёт при любой правке и сбрасывает актуальность кэша превью кожи.

## Что выяснено про Aseprite 1.3-rc4-dev

Эти наблюдения важны для совместимости; не убирайте обходные решения без повторной проверки.

### Ограничения и обходные решения

- `require()` не находит модули расширения ожидаемым образом. Поэтому всё собирается в один `main.lua`, а `require` внутри бандла подменён.
- `Dialog:tab` отсутствует в проверенной сборке. Запасной вариант — секции с разделителями вместо вкладок.
- Виджет с параметром `label=` занимает отдельную строку. Для компактности подписи создаются отдельными `dlg:label`.
- Консоль показывает только первую строку ошибки. Полный текст перехватывается через `xpcall` и показывается через `app.alert`.

### API / поведение, проверенные в этой среде

- `Dialog:canvas`, включая мышь и колесо.
- `GraphicsContext`.
- `dlg.bounds`.
- `sprite.data`.
- `sprite:newGroup`, `sprite:newLayer`, `sprite:newCel`.
- Экспорт слоями.

### Ещё не проверено

- `canvas.onkeydown` и горячие клавиши холста.
- `Timer` для Play.
- `sprite:newEmptyFrame` и `sprite:newTag`.
- Экспорт всей анимации.

## Принятые решения

- Делать **расширение**, а не отдельный редактор и не форк Aseprite. PhotoCraft и Pixelorama отвергнуты как избыточные для этой задачи.
- Использовать Bonebase как ориентир по **возможностям**, а не как код для изучения или копирования.
- Отложить отличительную фишку — «умные кости» — до достижения паритета по основным функциям.
- Экспорт перестраивает только группу **PixRig**. Сгенерированные слои заблокированы; пользовательские слои вне группы не затрагиваются.
- Для кожи и экспорта слоями нужен режим **RGB**.

## Как продолжить разработку / передача проекта

При продолжении в новом чате или передаче другому участнику:

1. Приложите актуальный `pixrig-<version>-src.zip` и этот паспорт проекта либо эквивалентный снимок репозитория.
2. Укажите, что именно проверено в Aseprite, включая версию сборки, скриншоты и сообщения об ошибках.
3. Не изучайте и не копируйте код Bonebase; ориентируйтесь на описанные цели по функциям.
4. Просите разработчика проверять каждую новую сборку в Aseprite и присылать результаты, при необходимости со скриншотами.
5. **Следующий шаг:** проверить этап 3 от начала до конца, затем перейти к IK и импорту GLB / BVH.

### Чек-лист проверки этапа 3

Используйте временный RGB-спрайт и фиксируйте фактический результат каждой проверки:

- [ ] Pose и Move изменяют нужные кости / смещения корня.
- [ ] Ключи создаются и открываются повторно без потери индексов костей и кадров.
- [ ] Интерполяция linear и step даёт ожидаемые позы.
- [ ] Timeline открывается и синхронизируется с правками.
- [ ] Play запускается, переключает кадры и корректно останавливается; проверить работу `Timer`.
- [ ] Горячие клавиши холста работают; проверить `canvas.onkeydown`.
- [ ] Copy / Paste Pose сохраняет нужную позу.
- [ ] Экспорт всей анимации создаёт ожидаемые кадры; проверить `sprite:newEmptyFrame`.
- [ ] Тег анимации и длительности кадров корректны; проверить `sprite:newTag`.
- [ ] Экспортированные слои соответствуют группам кожи и цветам; сторонние пользовательские слои не меняются.
- [ ] Undo / Redo и повторное открытие спрайта сохраняют ожидаемые данные рига.
- [ ] Ошибки показывают полный текст диагностики через `app.alert`.

Отмечайте этап 3 как проверенный только после успешного прохождения соответствующих проверок в Aseprite.
